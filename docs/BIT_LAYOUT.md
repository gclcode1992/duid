# ID 位布局说明

## 1. 总体结构

64 bit long，最高位（符号位）恒为 0，保证 HTTP 返回正十进制数字。

```text
 63        62                    22 21    16 15     3 2    0
+---+----------------------------+--------+---------+------+
| 0 |   毫秒时间戳               | worker |  序列   | 回拨 |
+---+----------------------------+--------+---------+------+
```

## 2. 默认方案4（6+13+3）

| 字段 | 位数 | 范围 | 容量说明 |
|------|------|------|----------|
| 符号位 | 1 | 0 | 固定为 0 |
| 时间戳 | 41 | 0 ~ 2^41-1 | 相对 epoch，约 69 年 |
| workerId | 6 | 0 ~ 63 | 最多 64 个并发副本 |
| 序列号 | 13 | 0 ~ 8191 | 单实例单毫秒最多 8192 个 ID |
| rollbackGen | 3 | 0 ~ 7 | 可区分 7 次时钟回拨 |

**约束公式：**

```text
1 + timestamp-bits + worker-bits + sequence-bits + rollback-bits = 64
```

## 3. 拼装与反解

### 拼装

```text
ID = (ts << 22) | (workerId << 16) | (sequence << 3) | rollbackGen
```

### 反解（默认）

```java
long gen      = id & 0x7L;
long sequence = (id >> 3)  & 0x1FFFL;
long workerId = (id >> 16) & 0x3FL;
long ts       = (id >> 22) & 0x1FFFFFFFFFFL;
```

反解掩码由 `BitLayoutProperties` 根据配置动态计算。

## 4. 备选方案对照

| 方案 | worker | 序列 | 回拨 | 最大副本 | 每毫秒/实例 | 回拨次数 |
|------|--------|------|------|----------|-------------|----------|
| 1 | 8 | 12 | 2 | 256 | 4096 | 3 |
| 2 | 7 | 13 | 2 | 128 | 8192 | 3 |
| 3 | 7 | 12 | 3 | 128 | 4096 | 7 |
| **4（默认）** | **6** | **13** | **3** | **64** | **8192** | **7** |

切换方案时修改 `application.yml` 中 `duid.id-layout.*`，须保证总和恰好 64 bit。

## 5. 示例 ID 解读

假设：`ts=83412000123, workerId=5, sequence=1007, gen=1`

```text
ID = (83412000123 << 22) | (5 << 16) | (1007 << 2) | 1
   ≈ 349876602913246589（18 位十进制）
```

| 字段 | 值 |
|------|-----|
| 时间戳 | 83412000123 ms（相对 epoch） |
| workerId | 5 |
| 序列 | 1007 |
| rollbackGen | 1（回拨期发号） |

## 6. 启动自检规则

`BitLayoutValidator` 在启动时校验：

1. 各字段位数 ≥ 1（timestamp ≥ 32）
2. **总位数恰好 = 64**
3. **数据位数恰好 = 63**（符号位占 1 bit）

不足 64：优先增大 `timestamp-bits` 补齐。  
超过 64：减少某位（如 worker-bits 或 timestamp-bits）。
